# SaySlate 1.11.2 Manifest Shortcut Repair

This artifact records the correction made after Edge rejected version 1.11.1. Chromium's Commands API documentation explicitly states that `Ctrl+Alt` combinations are not permitted because they can conflict with `AltGr`.

### D1: Restore Reliable Extension Manifest Loadability

Files: `manifest.json`

#### Problem

- **Current Behavior(s):** Version 1.11.1 declared `Ctrl+Alt+O` as a native command, causing Edge to reject the entire manifest and remove the failed unpacked load from the extensions list.
- **Expected Behavior(s):** The manifest should load successfully while still providing a native command capable of initializing the active website.

#### Requirement(s)

- Use a Chromium-supported key combination and preserve the scoped active-tab injection permissions introduced for the initializer.

#### Solution(s)

- Bumped SaySlate to 1.11.2 and changed the native initializer to **Alt + Shift + S**, using “S” as the mnemonic for Slate.

---

### D2: Preserve Requested In Page Shortcut

Files: `floatingHost.js` and `background.js` (reviewed, unchanged)

#### Problem

- **Current Behavior(s):** Chromium cannot register the requested `Ctrl+Alt+O` combination natively, but the content script can still observe it within an ordinary website after the host is attached.
- **Expected Behavior(s):** The familiar shortcut should remain usable where browser manifest restrictions do not apply, with a valid native initializer available when injection is required.

#### Requirement(s)

- Keep the in-page listener and private command route while distinguishing their shortcut roles clearly.

#### Solution(s)

- Retained **Ctrl + Alt + O** as the page-level toggle and used **Alt + Shift + S** as the native on-demand initializer.

#### Validation Details

- User validation found that **Ctrl + Alt + O** did not perform the expected in-page initialization.
- The user determined that this initializer was not important enough to retain, so version 1.11.3 removes it instead of pursuing corrective work.

---

### D3: Add Invalid Shortcut Regression Guard

Files: `tests/verify.mjs`

#### Problem

- **Current Behavior(s):** Earlier static verification compared the manifest against the intended shortcut string but did not encode Chromium's forbidden-combination rule, so it incorrectly approved an unloadable manifest.
- **Expected Behavior(s):** Command-line verification should reject known-invalid native shortcut combinations before Edge is asked to load the extension.

#### Requirement(s)

- Assert the valid initializer and fail whenever a native shortcut contains `Ctrl+Alt`.

#### Solution(s)

- Updated the expected native command to `Alt+Shift+S`, added the forbidden-combination assertion, and made this review artifact a required project file.

### D4: Correct Documentation And Validation History

Files: `README.md`, `ROADMAP.md`, `CHANGELOG.md`, and the 1.11.0 and 1.11.1 review artifacts

#### Problem

- **Current Behavior(s):** Documentation described 1.11.1 as a working native initializer even though the browser rejected it before live testing.
- **Expected Behavior(s):** The record should preserve the failed attempt, identify the exact rule that was missed, explain both current shortcuts, and leave overlay validation open.

#### Requirement(s)

- Correct current instructions without erasing the chronology or marking untested behavior complete.

#### Solution(s)

- Added the 1.11.2 release record, marked 1.11.1 as an unloadable regression, corrected shortcut guidance, and linked this artifact from the earlier reviews.
