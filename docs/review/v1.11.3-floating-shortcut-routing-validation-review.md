## Review Summary

Version 1.11.3 resolves the focus gap in code and command-line verification. Live browser validation remains pending because no automated browser was launched and microphone-dependent behavior requires the user's active extension profile. The retired `Ctrl+Alt+O` initializer is not treated as an open defect.

### D1: Route Shortcuts To Active Floating Overlay

Files: `shortcutProtocol.js`, `floatingHost.js`, `floating.js`, and `floating.html`

#### Problem

- **Current Behavior(s):** Floating shortcuts were listened for only inside the extension iframe. Clicking the host website moved focus away from that listener, so the website received the keys and the overlay did nothing.
- **Expected Behavior(s):** While Floating Slate is open, its established shortcuts should control that overlay whether focus is inside the iframe or on the underlying website.

#### Requirement(s)

- Capture supported shortcuts at the top-level page only while an overlay exists, then route each action privately to the matching floating session.

#### Solution(s)

- Added one shared shortcut protocol, loaded it in both contexts, and made the host relay recognized actions through a session-scoped extension message.
- Shortcuts pressed during iframe startup are queued until its load event, preventing an early action from being discarded.
- The host does not consume these shortcuts when Floating Slate is closed.

#### Validation Details

- [x] Open Floating Slate with **Alt + Shift + S** on an ordinary website.
- [x] Click the underlying website, press **Ctrl + Alt + D**, and confirm dictation starts in Floating Slate.
- [x] Confirm the underlying website does not also act on the captured shortcut.

### D2: Preserve Every Existing Floating Action Shortcut

Files: `shortcutProtocol.js` and `floating.js`

#### Problem

- **Current Behavior(s):** The action mapping existed, but it was coupled to iframe-local keyboard events and could not be reused by the website host.
- **Expected Behavior(s):** Every existing floating action should behave identically regardless of which side captured its shortcut.

#### Requirement(s)

- Centralize shortcut recognition and route both local and relayed keys through the same action dispatcher.

#### Solution(s)

- Added `runShortcut` as the single floating action dispatcher for `D`, `C`, `X`, `G`, `E`, `R`, and `F`.
- Kept all original action meanings: dictation toggle, current-text copy, global clear, first pass, second pass, processed-result copy, and guarded finish workflow.

#### Validation Details

- [x] Validate **Ctrl + Alt + D** starts and stops dictation.
- [x] Validate **Ctrl + Alt + C** and **Ctrl + Alt + R** copy the intended text.
- [x] Validate **Ctrl + Alt + X**, **G**, **E**, and **F** perform their documented actions.

### D3: Close Floating Overlay Before Page Escape

Files: `shortcutProtocol.js`, `floatingHost.js`, and `floating.js`

#### Problem

- **Current Behavior(s):** Escape closed the overlay only when the iframe held focus. With website focus, Escape passed through to the website and Floating Slate persisted.
- **Expected Behavior(s):** Escape should close Floating Slate first whenever it is open, regardless of whether the website or iframe currently holds focus.

#### Requirement(s)

- Intercept Escape at both focus boundaries, stop page propagation, close the overlay, and cancel its speech controller during teardown.

#### Solution(s)

- The page host now consumes Escape and removes the overlay directly when website focus is active.
- The iframe retains its local Escape close path, and unload cancellation stops speech and pending recovery attempts.

#### Validation Details

- [x] With website focus, press Escape and confirm Floating Slate closes without triggering the page action.
- [x] Reopen it, focus its transcript, press Escape, and confirm the same result.

### D4: Keep Native Toggle And Close Controls

Files: `manifest.json`, `background.js`, `floatingHost.js`, and `floating.js`

#### Problem

- **Current Behavior(s):** Adding focus-independent actions could have created a competing close route or changed the supported native initializer.
- **Expected Behavior(s):** The valid native toggle, visible close button, and repeated native toggle should continue closing the same active overlay cleanly.

#### Requirement(s)

- Preserve the supported browser command and existing private host-close route while retiring only the failed `Ctrl+Alt+O` page initializer.

#### Solution(s)

- Retained **Alt + Shift + S** as the browser-native open/close command and retained the close button's session-scoped request.
- Removed the unsuccessful page-level **Ctrl + Alt + O** listener so it is no longer presented as supported behavior.

#### Validation Details

- [x] Close the overlay with its close button.
- [x] Close the overlay by pressing **Alt + Shift + S** a second time.

### D5: Verify Shortcut Routing Without Launching Edge

Files: `tests/shortcut-protocol.test.mjs`, `tests/background-routing.test.mjs`, and `tests/verify.mjs`

#### Problem

- **Current Behavior(s):** Earlier checks verified iframe-local shortcut strings but did not prove a reusable recognizer, session validation, or correct two-file injection order.
- **Expected Behavior(s):** Repeatable command-line tests should catch routing regressions without opening Edge or requesting microphone access.

#### Requirement(s)

- Test all supported keys, rejected modifiers and repetitions, Escape recognition, session mismatches, manifest load order, and injection fallback order.

#### Solution(s)

- Added a focused protocol unit test and expanded static/background verification to cover both declared and on-demand host loading.
- Ran the checks through Node only; no browser process was launched.
