## Review Summary

Version 1.11.4 successfully exposed the ChatGPT-specific action, focus-independent shortcut, guarded submission state, and ChatGPT insert-only behavior during live validation. D2 and D3 retain narrower pending checks. D5 is blocked because testing on another website exposed a separate cross-site speech defect: Floating Slate opened, but dictation was unusable where microphone access had not been approved. Version 1.11.5 supersedes that host-bound speech architecture.

## Observed Defect And Follow-Up

Floating speech recognition ran inside the website-embedded iframe, leaving availability dependent on the host website's microphone permission boundary. This finding does not measure D3's ChatGPT composer-target requirement, so it is recorded separately rather than using a noncanonical D3 status. The corrective [v1.11.5 review](v1.11.5-extension-owned-speech-service-validation-review.md) moves floating recognition into an extension-owned offscreen document.

### D1: Add Dedicated ChatGPT Submit Action

Files: `floating.html`, `floating.css`, `floating.js`, and `shortcutProtocol.js`

#### Problem

- **Current Behavior(s):** Floating Slate exposed only the general finish control, which inserted text and closed without submitting.
- **Expected Behavior(s):** ChatGPT should expose a clearly separate action that communicates the additional submission step.



#### Requirement(s)

- Add one icon-only control and one focus-independent shortcut without changing or visually conflating the existing finish action.



#### Solution(s)

- Added a ChatGPT-only send icon with the tooltip `Process all enabled phases, insert, and submit` and **Ctrl + Alt + S**.
- The host identifies the current surface when opening the iframe, so the control stays hidden outside ChatGPT.



#### Validation Details

- [x] Open Floating Slate on ChatGPT and confirm the send icon appears.
- [x] Open Floating Slate on another website and confirm the send icon is absent.
- [x] Refocus the ChatGPT page and confirm **Ctrl + Alt + S** still reaches the overlay.

### D2: Reuse Guarded End To End Workflow

Files: `floating.js`

#### Problem

- **Current Behavior(s):** Adding an independent submission implementation could bypass the ordered stop, first-pass, optional second-pass, and failure gates already used by Finish.
- **Expected Behavior(s):** The ChatGPT action should differ only after the normal processing stages have completed successfully.



#### Requirement(s)

- Reuse the existing guarded workflow and select a different host action only at the final insertion stage.



#### Solution(s)

- Parameterized `finishWorkflow` so both actions share every preceding stage; ChatGPT selects `insert-submit`, while **Ctrl + Alt + F** continues selecting `insert`.
- Any stop or AI failure returns before insertion or submission begins.



#### Validation Details

- [x] Start dictation and invoke **Ctrl + Alt + S** without stopping first.
- [ ] Confirm both configured processing passes run in order before insertion and submission.

### D3: Require Verified ChatGPT Composer Target

Files: `chatGPTAdapter.js` and `floatingHost.js`

#### Problem

- **Current Behavior(s):** A generic page insertion target is not sufficient evidence that automatic submission is safe.
- **Expected Behavior(s):** Automatic submission should be possible only on ChatGPT when the saved target is its message composer.



#### Requirement(s)

- Validate the hostname and composer before inserting, and never convert a clipboard fallback into a send action.



#### Solution(s)

- Added a dedicated adapter that accepts `chatgpt.com` and its subdomains and recognizes `#prompt-textarea` or a qualifying composer textarea.
- Wrong targets, unsupported pages, changed targets, and clipboard fallbacks return errors while preserving the finished text.



#### Validation Details

- [x] Open Floating Slate from a non-composer field on ChatGPT and confirm submission is refused.
- [ ] Change or remove the composer while processing and confirm no send occurs.

### D4: Wait For Safe ChatGPT Submission State

Files: `chatGPTAdapter.js` and `floatingHost.js`

#### Problem

- **Current Behavior(s):** Clicking ChatGPT submit immediately after DOM insertion can race its interface before the composer state and send control are ready.
- **Expected Behavior(s):** Submission should occur once, only after the inserted result is observable and the send control is enabled.



#### Requirement(s)

- Poll for explicit readiness with a bounded ceiling and report failure without clearing or closing the overlay.



#### Solution(s)

- Reused ChatGPT Dictate's readiness pattern: confirm inserted text, locate `#composer-submit-button`, reject disabled states, and wait at 150-millisecond intervals for no more than 20 seconds.
- A timeout leaves the text in the composer, keeps the transcript in Floating Slate, and does not click submit.



#### Validation Details

- [x] Confirm a ready composer submits exactly once.
- [x] Confirm a disabled or missing send button eventually reports an error without submission.

### D5: Preserve General Finish Workflow Behavior

Files: `floating.js`, `floating.html`, and `README.md`

#### Problem

- **Current Behavior(s):** The established **Ctrl + Alt + F** action intentionally inserts without submitting so the user can review or continue editing.
- **Expected Behavior(s):** Adding the faster ChatGPT action must not change that safer general behavior.



#### Requirement(s)

- Keep separate controls, shortcuts, host actions, and documentation for insert-only and insert-and-submit intent.



#### Solution(s)

- Retained **Ctrl + Alt + F** and its existing button as `insert`; only **Ctrl + Alt + S** and the ChatGPT send icon request `insert-submit`.



#### Validation Details

- [x] Use **Ctrl + Alt + F** in the ChatGPT composer and confirm the final text is inserted but not submitted.
- [ ] Confirm the standard Finish control behaves the same on another website.
