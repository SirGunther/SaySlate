## Review Summary

Version 1.11.5 corrects the architecture responsible for the cross-site microphone defect found during v1.11.4 validation. Floating recognition now runs in an extension-owned offscreen document instead of the website-embedded iframe. Command routing and speech-engine behavior pass automated checks; live microphone permission and cross-site dictation remain pending.

### D1: Move Floating Speech Into Extension Context

Files: `manifest.json`, `background.js`, `offscreen.html`, `offscreenSpeech.js`, `floatingSpeechClient.js`, `floating.html`, and `floating.js`

#### Problem

- **Current Behavior(s):** The overlay iframe instantiated speech recognition inside each host website. On a site without approved microphone access, Floating Slate opened but dictation was unusable.
- **Expected Behavior(s):** Floating dictation should be owned by SaySlate and remain available when the overlay moves between supported websites.



#### Requirement(s)

- Run DOM-dependent recognition in an extension context that is independent of the current host page, without opening another visible window or tab.



#### Solution(s)

- Added the scoped `offscreen` permission and created `offscreen.html` with the official `USER_MEDIA` reason.
- The service worker creates one extension-owned speech document on demand and relays only private extension messages. This follows the [Chrome Offscreen API](https://developer.chrome.com/docs/extensions/reference/api/offscreen) architecture for DOM and user-media work unavailable to service workers.
- Floating Slate now loads a lightweight speech client instead of instantiating `SpeechRecognition` in the website iframe.



#### Validation Details

- [x] Reload SaySlate and approve microphone access if the extension requests it.
- [x] Open Floating Slate on the website that previously failed and confirm **Ctrl + Alt + D** starts dictation.
- [x] Confirm a second ordinary website reuses the working extension speech context.

### D2: Preserve Shared Speech Recovery Behavior

Files: `speechEngine.js`, `offscreenSpeech.js`, `floatingSpeechClient.js`, and `floating.js`

#### Problem

- **Current Behavior(s):** Moving recognition across contexts could lose the shared retry controller, final/interim transcript handling, or ordered stop promise used by Finish.
- **Expected Behavior(s):** The corrected architecture should behave like the existing floating dictation workflow apart from the permission boundary.



#### Requirement(s)

- Keep the proven recovery engine intact and serialize every UI-relevant lifecycle event back to the initiating overlay.



#### Solution(s)

- The offscreen controller uses the unchanged `SaySlateSpeech` engine and forwards start, result, retry, fatal-error, session-end, and stop events.
- Final and interim recognition results are converted to plain serializable text before runtime delivery.
- Explicit stop settles before the guarded processing workflow continues; cancel and overlay teardown stop pending recognition work.



#### Validation Details

- [x] Start and stop dictation normally and confirm the final words remain intact.
- [x] Observe one recoverable interruption and confirm the Retrying and Resumed states still appear.
- [x] Close with Escape during dictation and confirm no retry restarts afterward.

### D3: Route Transcript Events By Session

Files: `background.js`, `offscreenSpeech.js`, and `floatingSpeechClient.js`

#### Problem

- **Current Behavior(s):** One extension-owned offscreen document can serve multiple browser tabs, so unscoped events could update the wrong overlay.
- **Expected Behavior(s):** Only the session that starts recognition should receive its transcript and lifecycle events.



#### Requirement(s)

- Include the unguessable floating session identifier in every command and event, ignore mismatches, and cancel an older active session before accepting a new one.



#### Solution(s)

- Added session identifiers to the complete speech message protocol and filtered every event in the floating client.
- Starting a different session cancels the prior offscreen controller before configuring the replacement.
- Listener teardown prevents a closed iframe from retaining a runtime event subscription.



#### Validation Details

- [x] Dictate in one ordinary tab, close Floating Slate, then start a new session in another tab.
- [x] Confirm transcript events appear only in the currently active overlay.
